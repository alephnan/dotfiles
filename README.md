# Arch WSL dotfiles

Portable configuration for an Arch-on-WSL terminal: Neovim, tmux, starship and
bash, themed **Catppuccin Mocha** throughout.

The files here are the source of truth. `bootstrap.sh` symlinks them into their
default locations in `$HOME`, so editing a file in this repo edits the live
config, and `git status` shows exactly how the setup has drifted.

## What's included

| Path | Links to | Contents |
|---|---|---|
| `.config/nvim/` | `~/.config/nvim` | lazy.nvim, Catppuccin Mocha, lualine, telescope, treesitter; relative line numbers, `unnamedplus` clipboard |
| `.config/starship.toml` | `~/.config/starship.toml` | minimal prompt (`directory git_branch git_status ❯`) on the Catppuccin Mocha palette |
| `.tmux.conf` | `~/.tmux.conf` | mouse, vi copy-mode, true colour, TPM, Catppuccin status bar pinned to the top |
| `.bashrc` | `~/.bashrc` | DrvFs-aware `LS_COLORS` fixes, starship init, `~/.local/bin` on `PATH` |
| `.bash_profile` | `~/.bash_profile` | sources `.bashrc` for login shells |
| `packages.txt` | — | core pacman packages |
| `windows/` | — | Windows Terminal fragment + Nerd Font notes (manual, see below) |

Plugin versions are pinned: `.config/nvim/lazy-lock.json` for Neovim, and the
TPM / `catppuccin/tmux` commits near the top of `bootstrap.sh` for tmux.

## Install on a new machine

```bash
git clone https://github.com/alephnan/dotfiles.git ~/dotfiles
cd ~/dotfiles
./bootstrap.sh
```

`bootstrap.sh` installs the packages, symlinks the configs, clones the tmux
plugins at their pinned commits, and restores the Neovim plugins from the
lockfile. It is idempotent — re-running it is a no-op.

Anything it replaces is moved to a timestamped `~/.dotfiles-backup-*` directory
rather than deleted. Existing symlinks are reported (with their old target)
before being replaced.

Then open a new shell: `exec bash -l`.

To re-run on a machine that is already set up, `./bootstrap.sh --skip-packages`
does everything except invoke pacman.

### A note on `lazy-lock.json`

`bootstrap.sh` runs `Lazy! restore`, which pins every plugin to the commit in
`lazy-lock.json`. lazy.nvim itself is the exception: `lua/config/lazy.lua`
bootstraps it from its `stable` branch before the lockfile is read, so on a fresh
machine it lands on whatever `stable` currently points at and rewrites its own
entry. Expect `git status` to show a one-line `lazy-lock.json` change after the
first bootstrap. Commit it or `git checkout --` it; either is fine, it does not
affect the other plugins.

### It refuses to run if a config path is overridden

Before linking, the script checks `XDG_CONFIG_HOME`, `STARSHIP_CONFIG` and
`NVIM_APPNAME`, and aborts if any of them points somewhere other than the
default. This is deliberate: with one of those set, the symlinks would be
created where nothing reads them and the config would silently not load. Unset
the variable, or adjust the script on purpose.

## Manual steps (not handled by bootstrap)

**1. Windows Terminal + Nerd Font** — see [`windows/README.md`](windows/README.md).
Without the Nerd Font the powerline separators and devicons render as tofu boxes.

**2. `/etc/wsl.conf`** — root-owned, so it is applied separately:

```ini
[boot]
systemd=true

[automount]
options = "metadata,umask=22,fmask=11"
```

Run `wsl --shutdown` from Windows afterwards. The `metadata` option matters for
more than tidiness: without it DrvFs fakes the exec bit on every file under
`/mnt/c`, and `.bashrc` detects this and neutralises the `ex` colour rule so the
whole drive does not show up green in `ls`. Once metadata is live, that branch
turns itself off and real executables colour correctly again.

**3. Git credential helper** — `~/.gitconfig` is not tracked here because it is
generated by the GitHub CLI. Reproduce it with:

```bash
gh auth login
gh auth setup-git
```

## Secrets

Nothing in this repo is a credential, and it should stay that way. Do not add
SSH private keys, `~/.config/gh/hosts.yml` (it holds a live OAuth token),
`.env` files, or API keys. `.gitignore` blocks the obvious ones, but it is a
backstop, not a guarantee — check `git status` before committing.
